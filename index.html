001GoIn development2026

bastion-os

A containerised bastion / jump-host platform that brokers secure, audited access to internal infrastructure. The design premise: a bastion is a protocol-aware proxy, not an SSH box you log into. It authenticates the human against an OIDC identity provider, authorises the specific target under deny-by-default RBAC, opens its own connection with a managed credential, and records the session — so users never hold the target's real secrets.

About

I am a software engineer in Kochi, Kerala, currently a Software Development Engineer at Nav Technologies, where most of my work is financial infrastructure: multi-tenant lending platforms, a payment gateway orchestrating transactions across multiple banks, and the queueing that keeps all of it honest when something fails at 2am.

That is the thread through everything I build — systems where correctness is not optional. A watchdog that reruns a stalled job instead of swallowing it. Transaction-safe processing for an NBFC moving ₹1+ Cr a day. A bastion that proxies and records access instead of handing out keys.

I like the range too. I have shipped an ARKit app to 10,000+ downloads, scaled a real-time Next.js product to a thousand students across three campuses, published an npm package so other developers could skip the FIDO2 spec, and led the tech for TEDxCUSAT.

I graduated in Computer Science from CUSAT in 2025 and have been pushing code to GitHub since 2019. If you are building something that has to be both secure and actually shippable, I would like to hear about it.
